# هما (Homa)

نرم‌افزار دسکتاپ مدیریت مشتریان، جلسات و مالی برای آموزشگاه/مرکز خدمات. با کارت RFID حضور در جلسه ثبت می‌شود.

محصول نهایی روی ویندوز به‌صورت نصب‌کننده NSIS با نام **هما** ساخته می‌شود.

## امکانات

- داشبورد: مشتریان فعال، جلسات هفته جاری، درآمد ماه، وضعیت دستگاه RFID
- مدیریت مشتریان: ایجاد، ویرایش، حذف، جستجو و صفحه‌بندی
- دوره و جلسات: تعداد جلسه، هزینه، زمان‌بندی روی تقویم هفتگی (شنبه تا جمعه)
- ثبت حضور با کارت RFID (تلرانس ۲۰ دقیقه نسبت به ساعت جلسه)
- تقویم هفتگی برای مشاهده رزرو همه مشتریان
- گزارش مالی: درآمد ماهانه، نسبت جلسات استفاده‌شده، آخرین تغییرات هزینه

## پیش‌نیازها

- Node.js ۱۸ یا بالاتر
- npm
- ویندوز (هدف اصلی بسته‌بندی)
- خواننده RFID سریال (اختیاری؛ بدون آن بقیه بخش‌ها کار می‌کنند)

## نصب و اجرا

```bash
npm install
npm run dev
```

`npm install` ماژول‌های native (`better-sqlite3` و `serialport`) را برای Electron بازسازی می‌کند.

حالت توسعه دو فرآیند را با هم اجرا می‌کند:

1. Vite روی `http://localhost:5173` (رابط React)
2. Electron بعد از آماده شدن Vite

## ساخت نسخه نهایی

```bash
npm run build    # کامپایل renderer و main process
npm run dist     # ساخت نصب‌کننده در پوشه release/
```

خروجی ویندوز: `release/` با نصب‌کننده NSIS.

## معماری

```
┌─────────────────────────────────────────────┐
│  renderer (React + Vite + Zustand)          │
│  HashRouter — صفحات: داشبورد، مشتریان،      │
│  جلسات، مالی                                 │
└──────────────────┬──────────────────────────┘
                   │ contextBridge (preload)
                   ▼
┌─────────────────────────────────────────────┐
│  electron main                               │
│  IPC handlers + RFID serial + SQLite         │
└─────────────────────────────────────────────┘
```

- **Main process:** `electron/` — پنجره، IPC، دیتابیس، سریال RFID
- **Preload:** `electron/preload.ts` — فقط کانال‌های مجاز را به renderer می‌دهد
- **Renderer:** `renderer/` — رابط کاربری فارسی (RTL)
Renderer از `shared/types.ts` و فرآیند اصلی از `electron/db/types.ts` برای نوع‌های دامنه استفاده می‌کنند.

پنجره بدون فریم است؛ دکمه‌های minimize/maximize/close در نوار بالای UI هستند.

دیتابیس SQLite در مسیر userData ویندوز ذخیره می‌شود، نه کنار سورس:

`%APPDATA%/هما/database.sqlite` (نام پوشه ممکن است بر اساس `productName` باشد)

## مدل داده

| جدول | نقش |
| --- | --- |
| `Users` | مشتری (نام، تلفن یکتا، کد ملی یکتا، UID کارت) |
| `Courses` | دوره هر مشتری (هزینه، تعداد جلسات) |
| `Sessions` | زمان هر جلسه (`date` به‌صورت ISO-8601)، وضعیت استفاده |
| `SessionLogs` | لاگ تغییر هزینه دوره برای گزارش مالی |

هر مشتری در UI با **آخرین دوره** کار می‌کند. جلسات به دوره وصل‌اند و با حذف مشتری (CASCADE) پاک می‌شوند.

ستون `Users.average` از مهاجرت قدیمی مانده و در منطق فعلی استفاده نمی‌شود.

## RFID

1. برنامه پورت سریال را باز می‌کند (۹۶۰۰ baud).
2. اگر متغیر محیطی `RFID_PORT` باشد (مثلاً `COM3`) همان پورت استفاده می‌شود؛ وگرنه اولین پورت غیر بلوتوث.
3. خط ۱۰ کاراکتر هگز (`0000000000` تا `FFFFFFFFFF`) یعنی UID کارت.
4. اگر صفحه ساخت/ویرایش مشتری باز باشد، UID روی فرم می‌نشیند و جلسه مصرف نمی‌شود.
5. در بقیه صفحات، اگر جلسه‌ای برای همان روز در بازه ۲۰ دقیقه باشد، `used` می‌شود.

قطع و وصل دستگاه با reconnect خودکار مدیریت می‌شود. اگر هنگام شروع هیچ پورتی نباشد، هر چند ثانیه دوباره جستجو می‌شود.

نمونه `.env`:

```
RFID_PORT=COM3
```

## محدودیت‌های فعلی

- فونت وزیر از CDN لود می‌شود؛ بدون اینترنت به فونت سیستم برمی‌گردد.
- اگر `RFID_PORT` تنظیم نشود، اولین پورت سریال غیر بلوتوث انتخاب می‌شود.
- در دیتابیس هر مشتری می‌تواند چند دوره داشته باشد؛ رابط فقط با آخرین دوره کار می‌کند.
- جلساتی که قبلاً با فرمت تاریخ محلی سیستم ذخیره شده‌اند ممکن است تا ذخیرهٔ دوباره در تقویم دیده نشوند. جلسات جدید با ISO-8601 ذخیره می‌شوند.
- تست خودکار وجود ندارد.


- **پنجره خالی در dev:** مطمئن شوید Vite روی پورت ۵۱۷۳ بالا آمده؛ Electron تا آماده شدن Vite صبر می‌کند.
- **خطای native module:** دوباره `npm install` بزنید تا `electron-builder install-app-deps` اجرا شود.
- **RFID آفلاین:** پورت را در Device Manager چک کنید و در صورت نیاز `RFID_PORT` را در `.env` بگذارید.
- **فونت وزیر:** در توسعه از CDN لود می‌شود؛ بدون اینترنت به فونت سیستم برمی‌گردد.
